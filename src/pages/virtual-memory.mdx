{/* 4. EXPLANATION / DEEP DIVE */}
<section class="ml-section animate-fade-up" id="deep-dive">
  <div class="ml-section-header">
    <span class="ml-section-label">Deep Dive</span>
    <h2 class="ml-section-title">Why Direct Access Failed</h2>
    <p class="ml-section-subtitle">
      Early operating systems let programs directly access physical RAM. This caused three massive problems.
    </p>
  </div>

  <div class="ml-prose">
    <h3>Problem 1: The Wild West (Security)</h3>
    <p>
      In early operating systems, there was no memory protection. Some programs could accidentally (or maliciously) write data into another program's memory space. This would instantly cause your computer to crash with a Blue Screen of Death. 
    </p>
    <p>
      <strong>The Fix:</strong> Virtual Memory gives each program its own isolated "Virtual Space." It literally has no way to access another program's physical memory because the OS handles the mapping.
    </p>
    <SecurityVisualizer client:load />
    
    <br/>
    <h3>Problem 2: Insufficient Memory (Demand Paging & Swap)</h3>
    <p>
      Modern computers need a lot of memory. If you only have 8GB of RAM but try to open 10GB worth of programs, an old OS would simply throw an "Out of Memory" error.
    </p>
    <p>
      <strong>The Fix:</strong> The OS uses a <strong>Swap File</strong> on your Hard Disk. When RAM is completely full, the OS takes idle programs and "swaps" them to the disk. When you need them again, it swaps them back into RAM. This is called <em>Demand Paging</em>. It makes your memory feel infinite (though it costs some speed).
    </p>
    <SwapVisualizer client:load />

    <br/>
    <h3>Problem 3: Wasted Memory (Shared Pages)</h3>
    <p>
      Imagine you have 4 programs running, and they all need to use the Standard C Library (libc) to do basic math. In an old OS, that library gets loaded into RAM 4 separate times, wasting huge amounts of space.
    </p>
    <p>
      <strong>The Fix:</strong> Because the OS translates Virtual addresses to Physical ones, it can point the virtual memory of all 4 programs to the <em>exact same physical copy</em> of the library in RAM. We call this <strong>Shared Pages</strong>.
    </p>
    <SharedLibraryVisualizer client:load />

  </div>
</section>
