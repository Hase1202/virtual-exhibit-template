{/* 4. EXPLANATION / DEEP DIVE */}
<section class="ml-section ml-section--narrow animate-fade-up" id="deep-dive">
  <div class="ml-section-header">
    <span class="ml-section-label">Deep Dive</span>
    <h2 class="ml-section-title">Making Sense of the Mess</h2>
  </div>

  <div class="ml-prose">
    <h3>The Parking Lot Analogy (Fragmentation)</h3>
    <p>
      Imagine a busy parking lot. Cars are entering and leaving all day. By 3 PM, there are 20 empty parking spaces, but they are scattered randomly across different aisles. 
    </p>
    <p>
      Suddenly, a massive 18-wheeler truck arrives. It needs 5 parking spaces <strong>right next to each other</strong>. Even though there are 20 spaces total, the truck can't park because there is no single gap big enough. This is exactly what happens in your computer's RAM. We call this <strong>External Fragmentation</strong>.
    </p>

    <h3>The Valet Solution (Paging & Virtual Memory)</h3>
    <p>
      What if instead of forcing the truck to park in one piece, you could magically detach its cargo boxes and park them in individual, scattered spots? 
    </p>
    <p>
      This is <strong>Paging</strong>! The OS chops a large program into fixed-size chunks (Pages). The program itself (the truck driver) has no idea this happened—it sees a beautiful, clean <strong>Virtual Address Space</strong>. But physically, the data is scattered everywhere.
    </p>
    
    <h3>The Ledger (Page Table)</h3>
    <p>
      If the data is scattered, how do we find it? The OS keeps a giant list called the <strong>Page Table</strong>. Every time the program asks for data, the CPU looks at the Page Table to find out which physical gap the data is hiding in.
    </p>
  </div>
</section>
